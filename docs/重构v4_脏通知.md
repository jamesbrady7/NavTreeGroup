# 引擎 v4 重构设计：脏通知契约（perf-round2 分支）

> 2026-10-06 定稿。动机（用户原话归纳）：性能优化堆出来的机械（纪元闸门/双位置索引/
> 提示位图/就地比对）让代码杂乱难懂，进内网后没有大模型支持难以调试，而且跨调用
> O(k²) 依然没解决。用户决定**放宽使用侧**：调用方负责告诉引擎"何时脏、哪里脏"。
> 三目标：代码整洁流程清晰 > 性能内存最优 > 接口易用。冻结的只有 guibase 三政体
> 数据结构；引擎与调用契约都可以重设计。

## 1. 核心交换

**旧世界（v3，惰性发现）**：引擎不信任任何人，每次读都可能枚举活列表比对 lastLive
→ 为了不被这个成本压死，堆了纪元闸门（同操作免重验）、位置索引（免枚举答坐标）、
提示位图（免哈希探测）三层加速机械 → 每层都有自己的失效边界（R1/R2/C8 事故都出在这）。

**新世界（v4，通知失效）**：调用方在数据变更后调一次 `invalidate`（O(1) 置脏标志），
引擎读侧只查标志：**干净 = 直接答缓存，零枚举；脏 = 重算一次**。
- 跨调用 O(k²) **根除**（v3 文档承认只有这条路能治）。
- 纪元/位图/双索引全部删除，缓存检查从 30 行机械变成一行 `if (p.valid && !p.dirty) return;`。
- 代价：漏通知 = 投影陈旧。兜底三层（见 §5）。

## 2. 新公开 API（使用侧的全部义务）

```cpp
// ══ 数据侧变更通知（配对纪律：动完数据就调，可在批量操作末尾统一调）══
void invalidate(GuiBase* parent);       // parent 的孩子列表变了（增/删/移动/重排序）
void invalidateNode(GuiBase* node);     // node 自身属性变了（材质改名等影响 filter/grouping/less 的值）
void notifyRemove(GuiBase* parent, GuiBase* dying);
    // 便捷组合 = invalidate(parent) + discard(dying)。必须在 delete dying 【之前】调。
    // 级联删整棵子树：只需对子树根调一次（内部页变僵尸,prune 清）。
void invalidateAll();                   // 全部账页置脏（大变更后不想逐个报;下次读逐页收敛）
void setParanoidChecks(bool);           // 漏报检测开关（默认 _DEBUG 开、Release 关,见 §5）
bool paranoidChecks() const;
```

调用范式（生产三条流的对接点）：
- **精准删除流**（删除→begin/endRemoveRows）：`beginRowRemoval(par,row)` 前坐标照旧问引擎；
  执行删除处把原来的 `discard(v)` 换成 `notifyRemove(dataParent, v)`；其余不变。
- **新增流**：regime API 挂载（addTreeChild/addSubDataGroup/QObject  parenting）后 `invalidate(parent)`。
- **全量重建流**：beginFullReset → wipe（对每个被删根 `notifyRemove` 或干脆不报）→ rebuild
  →（rebind 或 prune+install）→ endFullReset。prune/rebind 本身全量自愈，wipe 阶段可以不逐个报。
- 属性变更（改名/换材质）：`invalidateNode(n)`。

**不做的事**（明确否决，防止复杂度回潮）：
- 不做"增量维护 flat/members"（通知里带 reason 做 O(1) 插删）——重算一页 = 一次枚举+流水线
  ≈ 微秒级,增量维护才是真正难调的状态机。通知接口收了 parent 就够,不收 reason。
- 不做线程安全/跨线程检测机械——与 QAbstractItemModel 同级的单线程契约,写进文档即可。

## 3. 引擎内部：删什么、留什么、换什么

### 删除（v3 的加速机械,全部随惰性发现一起死）
| 机制 | 原用途 | 死因 |
|---|---|---|
| EpochScope/m_queryEpoch/checkedAt/m_epochDepth/m_epochOptimOn/setEpochOptimization/crossThreadEntryCount/onOutermostEntry | 同操作内免重复校验 | dirty 标志天然免重复;R1 事故根源 |
| liveMatchesLast + revalidate 第 0 步双路径 | 零分配就地比对发现变更 | 不再需要"发现";组页自拆 UAF 防护只剩 dirty 路径一处 |
| m_nodePage（全局 66MB/M 节点） | parentOf/rowOf O(1) 跳过下钻 | 干净页下钻本来就免枚举,O(深度) 哈希足够;R2 事故根源（全局索引清理不对称） |
| memberToPos（每页 74MB 摊算） | 同上存 (父,行) | 与 memberToGroup **合并成一张 entries 表**（§4） |
| m_pageHint/m_groupHint 位图 + hintIndex/Probe/Mark（2MB + C8"建页点唯一"负担） | prune DFS 免哈希探测/RTTI | prune 是边界操作不是帧循环,省 60ms 不值一张永不回收的位图+一条易碎不变量 |
| installFromBinding 里的 revalidate 调用 | — | 页由 dirty 驱动,豁免逻辑简化为"同绑定→跳过" |

### 保留（是正确性契约或干净的封装,不是优化补丁）
- **m_retired + collectGarbage + noteRetired + retiredHighWater**（C1 读侧绝不释放;Qt persistent index 保命）
- **structRev**（C9 失步自检;递增条件不变）
- **PtrSet**（自包含干净类,prune DFS 的 20× 提速是真的;与杂乱无关）
- **bindId/bindGen 同绑定豁免**（rebind 不重跑流水线;语义在 v4 更简单:同绑定→什么都不做,页脏不脏由通知/prune 决定）
- **lastLive**（降级为新角色:不再是每次读的比对钥匙,而是 §5 自愈/漏报检测的"上次重算时的快照"）
- pipeline.h 七个纯函数、ITreeSource、NavTreeModel、cascadeTarget、三政体生存法则（discard/registerRoot/prune/bindSpec/rebind）、组页自拆回查防护（dirty 重算路径仍会触发 owner 连锁淘汰）

### 替换
- `Projection.memberToGroup + memberToPos` → **一张 `entries`**（§4）。
- `Projection.valid` 语义不变 + 新增 `bool dirty`。缓存检查唯一形态:
  `if (p.valid && !p.dirty) return;`（revalidate 第 0 步,组页/普通页统一,不再有纪元与双路径）

## 4. entries 单表规格（每页唯一的节点→坐标表）

```cpp
struct PosEntry {              // treeprojection.h 命名空间级（pipeline.h 要用）
    GuiBase* container;        // 投影父亲:页 owner(直属落位/组落位) 或某个组(被分组)
    int      row;              // 在 container 孩子序列里的行号(flat 行 或 members 行)
};
std::unordered_map<GuiBase*, PosEntry> entries;   // Projection 成员
```
- 键集 = flat ∪ 各组成员（与旧 memberToPos 相同），**随页同生共死**——没有全局副本,
  R2 那类"登记/清理不对称"在结构上不可能再发生。
- 写:revalidate 末尾（flat 定序后 + members 定序后各一遍循环）。
- 读① parentOf/rowOf 共用私有 `locate(node)`：
  ```
  cur = 组的自然父=owner,数据节点=parentForTree();  row = -1
  while cur:
      cur 无页 → return {cur, row}         // row 来自上层(cur 是组时即成员行);透传父则 -1
      revalidate(cur) + 回查(组页自拆防护)
      e = entries[node]
      查无 → return {cur, -1}              // 本页没投影它(被过滤) → rowOf 扫 flat 得 -1
      row = e.row
      e.container == cur → return {cur, row}   // 直属 flat 行
      cur = e.container                        // 进组继续下钻(组可能有自己的页,deepest-wins)
  ```
  parentOf = locate().first；rowOf = row≥0 ? row : （透传父→虚接口线性扫 / 有页→扫 flat 得 -1）。
- 读② buildFlat 的 rep() 上溯:沿 entries 走,`container != owner` 就继续,等价旧 memberToGroup
  上溯。Pipeline::buildFlat 签名改收 `(flatParts, entries, owner)`；T5 同步改。
- 内存:一张哈希表替代"memberToGroup 54MB + memberToPos 74MB + m_nodePage 66MB = 194MB"
  → 约 70~80MB/M 节点。**账本 228MB → 预计 ~110MB**。

## 5. 漏通知的三层兜底（内网可调试性的正面回答）

1. **prune/rebind 自愈（Release 也在）**：prune 的 DFS 对每个账页做"枚举 vs lastLive"比对
   （页节点只占全树 ~1%,1 万页×100 孩子 ≈ 几 ms）,不一致 → 置脏 → 本次 revalidate 收敛,
   Debug 下同时 stderr 报一行"漏通知自愈: 页 owner=名字"。install/refresh/rebind 都带 prune
   → 一切卫生边界都是收敛点。**语义:忘了通知,陈旧最多活到下一次卫生边界。**
2. **paranoid 漏报检测（默认 _DEBUG 开）**：childCount 对干净页额外做同款比对,不一致 →
   stderr 明确指出哪个父节点漏了 invalidate + 当场自愈。开发期一跑 demo 就暴露漏报点,
   Release 关（`setParanoidChecks(false)` 可强开）。
3. **structRev**：调用方精准操作前后各取一次,形状漂移当场可见（既有 C9 工具,不变）。

## 6. revalidate 新骨架（对照旧版看删了多少）

```cpp
void revalidate(parent, p) {
    if (p.valid && !p.dirty) return;                 // ← 缓存检查的全部
    // 组页:先 freshMembers(触发 owner 重算) → 页被连锁拆掉则 return（防护保留）
    live = rawChildren(parent); p.lastLive.swap(live);
    // paranoid 或 prune 场景在这里可比对旧 lastLive 报漏通知（childCount/prune 侧做,此处不做）
    vis = filterLive(lastLive, spec.filter);
    oldAll / parts(两档 visSlot) / bucketByKey / shouldCollapse / matchReusable
    cull → dropProjection(g, defer=true)+noteRetired   （读侧触发路径绝不 delete,C1 不变）
    sortMembers → p.members → 建 entries(flat 行+成员行) → p.flat → p.groups
    // 保守传播:本页重算后,名下所有"有自己页"的组一律置脏（成员表可能变了;
    //   深度=组嵌套层数,置脏 O(组数),下次读各组自行收敛 —— 比"精确判断变没变"简单一个量级）
    for g in p.groups: if page(g) exists → page(g).dirty = true
    p.valid = true; p.dirty = false;
    if (deleted 非空 || flat 行数变 || 组数变) ++m_structRev;
    // valid 依旧最后置位（异常安全闸门,§1.5 契约不变）
}
```
invalidate 全家都只是置标志（invalidateNode 经 parentForTree 找到自然父的页置脏;
找不到页 = 无人投影它 = 无事发生）,**通知本身零重算**——批量变更天然合并。

## 9. 风险与对策

- **漏通知**：三层兜底（§5）+ 全 demo/测试自身就是"正确调用范式"的活文档。
- **组页保守置脏的过收敛**：owner 每重算一次,名下组页全脏 → 多一次组页重算。组页重算
  = 成员表比对级流水线,窄组微秒级;宽组场景实测回填。若成为热点再谈精确化（先简单后聪明）。
- **T21/T22/T23/probe 的分辨力**：迁移时每条断言配"反例对照"（旧契约行为注释在案）。
- **迁移面大**：逐文件小步编译,每步跑 unit_tests;顺序=引擎→tests→demos→bench/probe→docs。
